# Montra

Personal finance app with cash/manual PayPal expenses, category budgets, income and commitments, savings forecasts, gold/investment tracking, and notifications.

**Live app:** https://montra-61q.pages.dev/

## Recent features (Demo)

- **AI Chat:** Cloudflare Workers AI financial assistant with expense summaries and illustrative savings plans. Chat-declared income is not saved automatically; financial data supplied by the browser is not independently re-fetched by the AI endpoint.
- **Stock Recommendations:** US market research watchlist with Twelve Data quotes when available, quote timestamps, volatility/risk context and a link to AI Chat. These are research signals, not guaranteed buy opportunities.
- **Stock watch notifications:** attempts to save deduplicated watch alerts in the existing notification bell after sign-in, approximately every 15 minutes while Montra is open, and when returning to the tab. This is **not** an always-on background market monitor or closed-browser push alert.
- **Demo trading:** initiate a simulated fractional-share purchase from Stock Recommendations and proceed to PayPal **Sandbox** checkout. Sandbox payments do not move real money or purchase real securities; payment approval/capture can fail and must not be represented as a successful trade without verification.
- **Demo Portfolio Performance:** estimated unrealized profit/loss for completed simulated positions, using available recent quotes. Stale or missing quotes are excluded, and the calculation excludes fees, spreads and dividends.
- **Limitations:** stock research does not provide personalized investment advice; real brokerage execution, Egyptian exchange coverage and production real-money stock trading are **not connected**. Live end-to-end verification of the newest flows is still required.

## Hackathon technology requirement: PayPal + AI

Montra combines **PayPal Developer Platform (Sandbox)** and **Cloudflare Workers AI** in a finance education and simulated investing prototype.

### PayPal integration

- **PayPal Sandbox REST Orders API:** `supabase/functions/montra-paypal-sandbox/index.ts` requests sandbox access tokens, creates sandbox orders and processes payment confirmation/capture responses.
- **Supabase Edge Function:** the authenticated `montra-paypal-sandbox` endpoint handles `preview`, `create`, and subsequent demo-completion/verification actions; PayPal credentials are retrieved server-side, never placed in browser JavaScript.
- **Frontend:** `stock-recommendations-ui.js` initiates a demo purchase, calls the Supabase function and redirects to `sandbox.paypal.com` for approval. The `index.html` demo order and portfolio views show the resulting simulated records.
- Sandbox approval does **not** equal a real stock purchase. No live PayPal payment or brokerage execution is supported. PayPal Sandbox capture may fail; the UI must not imply that a failed capture was paid.

### AI integration

- **Cloudflare Workers AI** runs **Meta Llama 3.1 8B Instruct** (`@cf/meta/llama-3.1-8b-instruct-fp8-fast`) through the Cloudflare Pages Function `functions/api/financial-chat.js`.
- `financial-assistant-ui.js` provides the authenticated AI chat UI, passing a bounded, browser-supplied snapshot of expenses/goals and user questions to the server endpoint.
- The assistant explains budgeting, spending and savings scenarios; selected calculations are deterministic. It does not verify bank balances or execute trades.
- **Twelve Data** supplies available stock market quotes for research and demo portfolio valuations. Stock watch classifications are rule-based, not generated by the Llama model.

### Other services

- **Supabase Auth + PostgreSQL + Edge Functions** for user accounts, financial data and sandbox integration.
- **Cloudflare Pages + Pages Functions** for hosting and AI request handling.
- **GitHub** for version control. No optional hackathon sponsor integrations (AG Grid, APIMatic, Astropods, Bryntum, Channel3, Elastic, KERNEL, Postman, Render or Zapier) are claimed.

## Deployment and setup

1. Clone the repository and run `python -m http.server 8000` for a local static preview. The deployed app uses Cloudflare Pages with its `functions/` directory; the local Python server does **not** emulate the Cloudflare AI endpoint.
2. Create/configure a Supabase project. Review `supabase/schema.sql` and the migrations in `supabase/migrations/` **for a new database only**. Configure Auth, Row Level Security, allowed origins and redirect URLs.
3. Deploy the Supabase Edge Function under `supabase/functions/montra-paypal-sandbox/`. Configure the PayPal Sandbox app/client credentials in the server-side secret store as expected by the function and its database secret retrieval RPC. Never commit credentials.
4. Deploy to Cloudflare Pages and bind Workers AI as `AI` for the Pages Function. Configure the public site URL in Supabase Auth redirects and in the sandbox function's origin/return settings.
5. Sign in with a test account, open **Stock Recommendations**, request quotes, initiate a **Demo Buy**, and use PayPal **Sandbox** buyer credentials. Check approval/capture and the resulting demo order state separately.
6. Verify AI Chat and the demo portfolio after deployment. Some features require market-data API access and appropriate backend scheduling. Do not treat successful deployment alone as end-to-end validation.

**Security note:** Only publishable frontend keys belong in the client. PayPal secrets, Supabase service-role keys, market-provider credentials and Cloudflare AI bindings must remain server-side.

## Run locally

```sh
python -m http.server 8000
```

Open http://localhost:8000. The root index.html, locales.js, sw.js and logo.png form a buildless static app. Supabase provides authentication, storage and server functions. Browser publishable keys are public by design; database RLS protects user records.

## Backend

- supabase/schema.sql is the initial reconstructed schema; apply only to a new empty database, then review/apply subsequent migrations in order. Existing production databases already have these changes: do not replay migrations blindly.
- supabase/migrations contains asset tracking, country/currency ledgers, notification infrastructure, market prices and immediate first-quote triggers.
- supabase/functions/montra-market-sync fetches prices and values holdings.
- supabase/functions/montra-notifications delivers queued Web Push and optional email notifications.
- See each function README for Vault secrets, authentication and schedules. Enable pg_net and pg_cron, configure Auth site/redirect URLs and function CORS for your deployment. Project URLs in deployment SQL need replacing for a new project.
- Provider keys, VAPID private keys and job tokens belong in Supabase Vault. No secret values or customer data are included here.

## Features and limits

- Goals include linked asset valuations and estimated savings; forecasts are estimates, not guarantees.
- International gold reference: USD per troy ounce converted to grams, purity and ledger currency. It is not an Egyptian shop/buyback quote and excludes workmanship.
- First automatic quote is requested when an asset is created or its pricing configuration changes; periodic synchronization runs every five minutes. Pending assets are checked in the visible page every two seconds.
- ExchangeRate-API account endpoint uses a server-only key, 12-hour cache and a public-endpoint fallback. Daily FX can differ from bank transaction rates.
- Local Egyptian gold and stock adapters require provider keys and suitable exchange coverage; these are currently unconfigured.
- Price alerts use a cumulative percentage threshold and at most one alert per holding per hour. Web Push requires browser permission and device support. Email requires a configured provider and verified sender.
- Cash and PayPal expenses are manually entered. PayPal synchronization is not connected.
- Switching base currency selects a separate ledger; it does not convert historical entries.

## CSV expense import/export (incremental update)

Open **Transactions** after signing in and choose **Export CSV** to download the current currency ledger's expenses, or **Import CSV** to upload a CSV with columns `merchant,amount,expense_date,method,category,note`. Dates must be `YYYY-MM-DD`; methods must be `Cash` or `PayPal`; amounts must be positive. The import validates rows and shows counts/errors before writing to the existing `montra_expenses` table using the signed-in user's Supabase session and existing RLS. It skips invalid rows and duplicate rows **within the file**; it does **not** deduplicate against previously imported database records. Imports use batches of 100; if one batch fails, earlier batches may remain saved. Review the ledger before retrying. Only CSV is supported, not native XLSX. No database migration or new secrets are needed.

Test the CSV logic: `node --test tests/transaction-csv.test.cjs`. The existing suite has two pre-existing failures and must be fixed separately. This update has not been verified against a live Supabase account.
